This release of the [fork](https://github.com/snargit/GoogleTestAdapter) supports [Google Benchmark](https://github.com/google/benchmark). See the [README](https://github.com/snargit/GoogleTestAdapter#google_benchmark) for details.

* enhancement: the benchmarks of executables built with Google Benchmark are discovered and run: Test Explorer shows them with the source locations and namespaces of their functions or fixtures, and with trait *(Type,Benchmark)*; a benchmark fails if it calls `State::SkipWithError()`, is skipped if it calls `State::SkipWithMessage()`, and passes otherwise, with a summary of its measurement (e.g. `12.3 ns (CPU 12.1 ns), 56M iterations`) as message and the statistics of all its runs (including counters, labels, and the aggregates of repetitions) as output; crashes and timeouts are reported by the benchmark which was running, and with parallel test execution, the benchmarks are run after the tests
* enhancement: new option *Dry runs of benchmarks* (default true), which runs each benchmark for one iteration only (`--benchmark_dry_run`, Google Benchmark 1.9.1 or later) to check that it works; switch it off for real measurements
* enhancement: GTA's automation object reports the test framework of an executable (`testFramework`) and marks benchmarks as such (kind `Benchmark`)
* note: unlike Google Test, Google Benchmark exits with an error on unknown flags, so *Additional test execution parameters* meant for Google Test executables should be set in project settings rather than globally
* bugfix: with parallel test execution, no tests were run if the file containing the durations of an executable's tests could not be read (e.g. since it was no XML file, or was deleted while being read); now, the tests are scheduled without the durations
